# 锐捷开发平台提交部署前先同步最新合并代码

## 规则

针对锐捷开发平台项目，凡是涉及提交代码、推送、构建流水线、部署或发布，必须先同步远端最新状态，不能直接在旧本地提交上继续操作。

## 标准顺序

1. 确认目标仓库、目标分支、当前工作区和远端地址。
2. 检查工作区是否有未提交改动；如果有，先保护或确认，不能直接覆盖。
3. 执行 `git fetch --prune`，再对目标分支执行 `git pull --ff-only`，拉取已经合并到远端的最新提交。
4. 基于最新代码重新检查差异，确认本次改动仍然适用；如果有冲突或上游改动影响本次方案，先重新分析并解决。
5. 运行与本次改动相关的测试和构建检查。
6. 只提交本次预期文件，提交后推送目标分支。
7. 推送成功后再触发开发平台构建流水线。
8. 构建成功后再部署实例；生产发布、回滚、域名或证书变更仍需单独确认。
9. 部署后独立核验版本、实例、Pod、日志、健康检查和实际访问结果。

## 必须遵守的注意事项

- “拉取最新合并内容”必须发生在本次提交之前，而不是提交之后才同步。
- 不允许用强制 reset、force push 或覆盖用户未提交改动的方式解决同步问题。
- 如果 `pull --ff-only` 失败，停止提交、构建和部署，先报告分叉或冲突原因。
- 构建成功不等于部署成功，部署成功也不等于访问和业务功能正常；这些状态要分别验证。
- 生产环境、删除、回滚、DNS、SSL 和访问权限变更必须再次确认。

## 已验证背景

当前 AI-BI Platform 的迭代中曾经存在本地分支领先远端、同时远端已经有后续合并提交的情况。后续必须先同步最新合并版本，再将本次改动重放或重新合并，避免基于旧代码提交和部署。
